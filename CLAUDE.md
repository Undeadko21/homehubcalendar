# Заметки для разработки (читать перед любыми изменениями)

Проект: семейный календарь-агрегатор (FastAPI + SQLite + Vue 3; приложения Android, iPhone, Mac; навык Алисы).
Пользователь общается по-русски, интерфейс и комментарии на русском. Развёрнут на домашнем Proxmox в LXC с Docker,
обновляется автоматически из ветки `main` (`deploy/update.sh` по таймеру, раз в 15 мин).
Публичный адрес — `https://homehubcalendar.ru` (VPS с Caddy + обратный SSH-туннель домой). Репозиторий публичный: секретов в нём нет и быть не должно.

## Правила (нарушение = поломка прода)

1. **Любой пуш в `main` сразу уезжает в прод.** Перед пушем: `set -o pipefail; ./deploy/check.sh` (pytest бэкенда, `npm test`, сборка фронта, тесты Алисы) — пушить только при «OK: можно пушить».
   Крупное изменение — сначала помощник `reviewer` (см. ниже); рискованное (миграции, лента, снимок, запись) — ещё и песочница прода.
2. Миграции БД — только дописывать в конец `MIGRATIONS` (`backend/app/db.py`).
3. `deploy/update.sh`: байтовая длина текста ДО строки `git reset` не должна меняться (bash читает скрипт по смещению). Подробно — `docs/dev/changelog.md`, v0.11.2.
4. `.dockerignore` должен пропускать `android/release` и `android/version.properties` (без них образ не собирается; CI `docker` это ловит).
5. Android: подписной ключ `android/keystore/homehub-release.jks` не менять; выпуск — `versionCode` в `android/version.properties` + `./android/build-release.sh` + коммит `android/release`.
6. Swift (iPhone/Mac) здесь не собирается — только GitHub Actions (`ios.yml`, `macos.yml`), они же коммитят сборки с `[skip ci]`. Версии — `ios/version.txt`, `macos/version.txt`. Логи CI: `gh api repos/Undeadko21/homehubcalendar/actions/jobs/<id>/logs`.
7. Секреты (код подключения `hhc1.` с полем `t` — токен записи Диска, токены VPS/виджетов/дозора, пароль) не печатать в ответах, коммитах и логах. Пароли пользователя не вводить.
8. `frontend/src/lib/news.js` — записи «Что нового» добавлять В НАЧАЛО с новым `n`. После новой версии — дописать раздел в `docs/dev/changelog.md` и при необходимости в тематическую заметку.
9. `alice/function.zip` пересобирать после правок `alice/handler.py` (код в Yandex Cloud обновляет пользователь вручную).
10. Пользователь отказался от: «кто я» на устройстве, рабочих календарей одной полосой, VPN. Не предлагать снова.

## Проверка

```bash
set -o pipefail; ./deploy/check.sh          # всё сразу; падает при любой ошибке
python backend/tools/sandbox.py <база|копия --key k> [--ui]   # песочница прода: копия базы без секретов и сети (docs/dev/outside.md)
python backend/tools/shots.py               # снимки экранов на демо-данных → /tmp/shots (телефон, компьютер, тёмная тема)
```
Прод: `curl https://homehubcalendar.ru/api/health` (версия `0.x.y+<коммит>`), `/api/app`, `/api/app-ios`, `/api/app-mac` — без входа.
Сводка состояния для дозора: `GET /api/watch` с заголовком `X-Watch-Token` — версия, проблемы «Состояния», скорость, ошибки экранов; без календаря, списков, адресов (URL/e-mail вырезаются) и секретов; в тексте проблем бывают имена и названия событий. Токен — «Связь вне дома» → «Сервер и уведомления» → «Дозор разработки».

## После выкатки

После пуша в `main` GitHub Action `postdeploy.yml` ждёт обновления прода и проверяет его (письмо при провале). Состояние ещё и агентом, ~20 минут после пуша:
`WATCH_TOKEN=<токен дозора> ./deploy/postcheck.sh <коммит>` (токен — из задачи дозора/окружения, не из репозитория). Хуже, чем было, — сразу сообщить пользователю и откатить (`git revert` → check → пуш).

## Помощники (`.claude/agents/`)

- `reviewer` — независимое ревью изменений перед пушем (ошибки, безопасность, прод). Запускать на всём, что больше мелкой правки.
- `ui-tester` — снимки экранов (`backend/tools/shots.py`) и поиск съехавшей вёрстки, тёмной темы, узкого экрана.
- `architect` — короткий план перед крупной функцией (файлы, риски, совместимость со старыми приложениями); код не пишет.
- `executor` — одна часть крупной задачи в своей ветке/каталоге (`docs/dev/parallel.md`); в `main` не пушит.
- `apps-checker` — вычитка Swift/Kotlin, которые здесь нельзя запустить: совместимость с сервером, версии, CI.

Задачи по расписанию (в облаке, пишут на телефон): **утренний дозор** — ежедневно, только сообщает; **еженедельный ревизор** — по воскресеньям, правки только в ветке `review/<дата>` + pull request, в `main` не пушит.
