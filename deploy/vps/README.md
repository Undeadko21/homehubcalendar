# Календарь из любой точки мира: VPS + обратный SSH-туннель

```
телефон / браузер ──HTTPS──► VPS (Caddy, ваш домен) ──SSH-туннель──► домашний сервер (календарь)
                                                       ▲
                                          соединение открывает дом, порты на роутере не нужны
```

## 1. Что купить
- **VPS**: Ubuntu 22.04/24.04, 1 ядро, 512 МБ–1 ГБ, публичный IPv4 (от 200–400 ₽/мес; Timeweb, Selectel, Beget, REG.RU…).
- **Домен** (~200 ₽/год). В DNS добавьте A-запись `cal.ваш-домен` на IP VPS и подождите 5–30 минут.

## 2. Пароль вместо PIN (дома, до всего остального)
В `config/.env` на домашнем сервере задайте длинный пароль (12+ символов, можно фразой с русскими буквами):
```
HOMECAL_PIN=ваша длинная фраза
```
Затем `docker compose up -d` в папке проекта. Все устройства попросят войти заново (приложения Android/iPhone/Mac — тоже, один раз).

## 3. Дома (в LXC с Docker)
```bash
bash deploy/vps/setup-home.sh IP_VPS            # если календарь на порту не 8080 — добавьте его вторым аргументом
```
Скрипт создаст ключ, поставит службу `homehub-tunnel` (запускается сама и переподключается при обрыве) и **напечатает публичный ключ** — скопируйте строку `ssh-ed25519 ...`.

## 4. На VPS (от root, по SSH)
Скачайте или скопируйте `deploy/vps/setup-vps.sh` и выполните:
```bash
bash setup-vps.sh cal.ваш-домен "ssh-ed25519 AAAA... homehub-tunnel"
```
Скрипт поставит Caddy (HTTPS-сертификат сам), заведёт пользователя `tunnel` (только туннель на 127.0.0.1:18080, без оболочки), настроит `ufw` (открыты 22, 80, 443) и `fail2ban`.

## 5. Запуск и проверка
Дома: `systemctl start homehub-tunnel && systemctl status homehub-tunnel`.
Откройте `https://cal.ваш-домен` **с мобильного интернета** (не из домашней сети) и войдите паролем.

## 6. Приложения
В Android/iPhone/Mac-приложении укажите адрес `https://cal.ваш-домен` вместо домашнего (Настройки → адрес сервера) — так календарь работает и дома, и вне дома. Виджеты и напоминания продолжают работать и через облако Яндекс.Диска, если сервер или VPS недоступны.

## Безопасность
- Календарь защищён паролем; после 5 неверных попыток подряд вход блокируется (по настоящему IP клиента: Caddy передаёт его в `X-Forwarded-For`, приложение его учитывает).
- Описание API (`/docs`, `/openapi.json`) отключено; вход через HTTPS ставит cookie с флагом `Secure`.
- На VPS ключу туннеля разрешено только слушать `127.0.0.1:18080`, оболочки и других пробросов нет.
- Когда убедитесь, что заходите на VPS по ключу, отключите вход по паролю: `PasswordAuthentication no` в `/etc/ssh/sshd_config`, затем `systemctl reload ssh`.
- Не должно быть открытого порта календаря на роутере: наружу он выходит только через VPS.

## Если что-то не работает
- `https://домен` не открывается: DNS ещё не обновился (`dig +short cal.ваш-домен`), порты 80/443 закрыты у хостера, `journalctl -u caddy -n 50` на VPS.
- 502 Bad Gateway: туннель не поднят. Дома `journalctl -u homehub-tunnel -n 50`, на VPS `ss -ltn | grep 18080` (должен слушать).
- Туннель падает с «remote port forwarding failed»: на VPS остался старый сеанс, подождите минуту (служба переподключится сама).
